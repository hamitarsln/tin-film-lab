# Story

Gate 1. Three concepts for a 24–34 s launch film, then the pick.

What the viewer must leave with (BRIEF.md): **what Tin is**, **that their own agent drives it**, and **the one
command to try it**. Who watches: technical founders who ship daily with Claude Code, Codex or Cursor and have
no marketing person. Their product moves fast; their marketing is a blank page or a pile of one-off prompts.

Hard requirements carried into every concept: a hook in under 2 s; by 5 s the viewer knows Tin is a marketing
system their coding agent drives; the MCP command going into an agent; the agent filling Tin's plan from a
codebase; real catalogue workflows on a schedule; a decision waiting for approval; the biggest moment on the
drop; end on the wordmark, the command and tin.computer. Every word from BRIEF.md or refs/product/.

---

## Concept A: "Same agent, new job"

**Logline.** The coding agent that already ships your product takes on the marketing: one MCP command, it fills
Tin's plan from your codebase, and the plan becomes real workflows that keep running after the session ends.

**Hook line.** "Your agent ships the product." then, on the next bar, "Tin lets it run the marketing."

**Beat outline** (one continuous take, ~16 bars):
1. *Hook.* Warm paper. Huge Funktional Grotesk typed word by word on the beat: "Your agent ships the product."
   A terminal-blue strip, the agent's surface, already sits at the bottom of frame with a live caret.
2. *Promise.* Line two types under it: "Tin lets it run the marketing." Tin is named, marketing is named, the agent
   is named, all before 4 s.
3. *Plug in.* The caption's caret drops into the blue strip, which grows into the agent's terminal. The real
   command types with a human rhythm: `claude mcp add --transport http tin https://app.tin.computer/mcp`. Enter
   on a downbeat. Caption: "Paste one line into your terminal." (real dashboard copy).
4. *The agent works.* The real first prompt types: "Use Tin to grow my project like a pro!" The agent answers with
   the README's own reply ("I'll read the repository first…"). Tin's onboarding plan opens beside it and its real
   fields fill one per beat (`product_url`, `system_repository`, `system_search_console`, `priority`, `outcome`…).
   Caption: "No forms. It reads your code."
5. *Held breath.* The plan is ready. The cursor travels to approve it. The music's break: the bass drops out.
6. *Drop.* The click lands on the slam. The plan's lines snap into workflow cards and the camera springs back to
   reveal Tin's System view full of real catalogue workflows with schedules and running dots. The blue agent
   surface folds away, and the runs keep going. Caption: "A whole marketing system." then "60 workflows. Running
   between sessions."
7. *Decision.* One run stops at review. The Decisions count ticks to 1. The cursor opens it: a "Draft for X" post
   waiting for approval. Click Approve on a beat. Caption: "Review before anything ships."
8. *End card.* Approve's colour floods into the lime call to action: the Tin wordmark, the command, tin.computer,
   held through the fade.

**Why a technical founder tries it.** It starts from the tool they already trust and the action they already
know how to take: paste a line into their agent. It shows that nothing new has to be learned (the agent reads the
repo, no forms), that the result is bigger than a prompt (a system of 60 workflows on schedules), and that they
stay in control (approval). The call to action is the exact command they just watched work.

## Concept B: "Prompts forget"

**Logline.** One-off marketing prompts vanish when the session ends; Tin turns them into saved workflows with
inputs, a schedule and an approval step, so the work keeps going between sessions.

**Hook line.** "Prompts forget." then "Tin keeps going."

**Beat outline:**
1. *Hook.* An agent session with a marketing request and a long answer. The session ends and the answer un-types
   itself back to an empty caret. Caption: "Prompts forget."
2. The empty caret types the MCP command. Caption: "Tin keeps going."
3. A workflow is saved with its inputs and a schedule: "Run the organic traffic system", `site_url`, `market`,
   `article_weekdays`. Tin handles the timers and retries.
4. *Drop.* A week runs as a time-lapse: day columns tick by on the beat, runs fire, a retry recovers, one run
   waits for approval, the project wiki grows. Caption: "Work that continues between sessions."
5. Approve an article; it reaches the site as a pull request.
6. End card.

**Why a technical founder tries it.** It names a frustration they have felt (re-explaining the product to an
agent every session) and shows the precise fix: saved workflows, a schedule, context that carries forward.

---

## Concept C: "One line"

**Logline.** Everything Tin does unfolds out of the single line you paste into your coding agent.

**Hook line.** "One line." over the command typing in giant monospace, the camera tracking the caret.

**Beat outline:**
1. *Hook.* Extreme close-up: `claude mcp add --transport http tin` types across the frame in huge mono; the camera
   rides the caret. Caption: "One line."
2. The URL completes, Enter, pull back: it's inside an agent's terminal. "…and your agent runs marketing."
3. Each token of the command unfolds into part of the system: `tin` becomes the wordmark, `mcp` becomes the tools
   the agent can call ("Every workflow here becomes a tool your agent can call.").
4. *Drop.* The line bursts into the catalogue: workflow names flow into the seven areas as a typographic wall.
5. A decision is approved.
6. End: the camera returns to the one line, now with the wordmark and tin.computer.

**Why a technical founder tries it.** The call to action is the story, so the command is the thing they remember.
It is the most "keynote bumper" of the three.

---

## The pick: Concept A, "Same agent, new job"

It is the brief's one-liner turned into a film: *a coding agent already ships the product; plug in Tin and the
same agent starts running the marketing, as real workflows that keep going after the session ends.* Its hook
says agent and marketing in the first sentence and names Tin in the second, so "what is this" is answered by
~4 s. It walks through every required product moment in the order a founder would live them (command, plan
from code, system on schedules, approval), all with real UI driven by a cursor, and each beat grows out of the
last (caption caret → agent surface → plan → workflow cards → decision → lime end card). It also carries
Concept B's best idea as the drop's meaning: the agent's session folds away and the runs keep going.

**Why B loses.** Its first two seconds show a failure: an invented marketing prompt and an invented answer
being erased, which breaks the rule that every on-screen word is real, or needs an "example" label in the
hook, which kills it. The viewer doesn't see that Tin plugs into *their* agent until after second five, and the
week time-lapse invites invented dates and run counts. Its strength (continuity between sessions) survives as
A's drop.

**Why C loses.** It sells the command but not the product. The agent filling the plan from a codebase, the
workflows on schedules and the decision all become abstractions instead of real UI driven by a cursor, which
the brief asks for. "One line." alone doesn't say marketing or agent in the first two seconds, a typographic
wall of 60 names won't read on a phone, and giant mono as the main voice breaks the house split (Funktional
Grotesk for words, mono for chrome). Its best idea survives too: the command is A's call to action and its
end card, typed in full.
