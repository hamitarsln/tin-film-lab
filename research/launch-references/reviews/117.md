## Lessons

- Keep: Show the real object beside the offer, then give a visible entry-to-outcome sequence.
- Try: Shorten the problem section to one payment example and one authentication comparison, then compare time to describe the service.
- Try: For Tin, pair each shown approval problem immediately with its matching product action and visible result.
- Avoid: Treating trust labels, displayed odds or celebratory UI as independent proof of fairness and fulfilment.
- Still open: Draw terms, odds calculation, custody, authentication process, eligibility, real delivery and audio remain unverified.
